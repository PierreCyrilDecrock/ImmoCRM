# supabase/migrations

Fichiers SQL numérotés décrivant la base de données (`0001_…sql`, `0002_…sql`, dans l'ordre). Claude Code les applique via le connecteur Supabase : d'abord sur le projet de test, puis sur le projet réel une fois l'étape validée et avec l'accord explicite de l'utilisateur. La procédure est décrite dans `.claude/skills/supabase/SKILL.md`. Sans connecteur, le contenu d'un fichier peut toujours être collé à la main dans l'éditeur SQL de Supabase.

Les conventions que chaque table respecte sont dans [docs/donnees.md](../../docs/donnees.md). Un fichier déjà appliqué ne se modifie plus : toute correction passe par un nouveau fichier.

| Fichier | Contenu |
| --- | --- |
| `0001_fondations_reglages.sql` | Fonction `maj_updated_at()` et table `reglages` (une ligne par utilisateur) |
| `0002_contacts.sql` | Table `contacts` : personne ou société, coordonnées, rôles, étiquettes, source, « recommandé par », température |
| `0003_contacts_recherche.sql` | Colonnes `recherche`, `nom_tri` et `fusionne_dans_id` tenues par la base ; fonctions `normaliser_recherche`, `etiquettes_contacts`, `doublons_contact` et `fusionner_contacts` |
| `0004_contacts_recherche_ajustements.sql` | Retire cinq index que les règles d'accès par ligne rendent inutilisables ; accélère `doublons_contact` |
| `0005_contacts_consentement.sql` | Consentement et RGPD : origine et date de collecte, accord pour être appelé (date, preuve), client existant, opposition au démarchage, date du dernier contact ; table `appels_sans_accord` ; droit de suppression sur `contacts` et fonction `supprimer_contact_definitivement` ; fusion complétée |
| `0006_contacts_consentement_ajustements.sql` | Valeur par défaut (date du jour) pour `collecte_date` et `dernier_contact_le` |
| `0007_biens.sql` | Table `biens` (adresse, caractéristiques, prix, statut, DPE et GES, champs propres à chaque type) ; table `biens_proprietaires` (propriétaires d'un bien, quote-part facultative) ; table `biens_prix` (historique des prix, rempli par la base) ; fusion des contacts complétée |
| `0008_biens_photos.sql` | Espace de stockage privé `photos-biens` et ses règles d'accès ; table `biens_photos` (rang, photo principale, plafond de 20 par bien) ; fonctions `ordonner_photos_bien` et `espace_photos` |
| `0009_taches.sql` | Table `taches` (titre, motif, catégorie, priorité, date, heure et durée facultatives, lieu, état, liens vers un contact et un bien, récurrence) ; fonction `cloturer_tache` (clôture et création de l'occurrence suivante en une seule opération) ; fusion des contacts complétée |
| `0010_activites.sql` | Table `activites` (journal : type, résultat d'un appel, compte rendu, date et heure, durée, liens vers un contact et un bien) ; la date du dernier contact tient compte du journal (sauf les notes) ; fusion des contacts complétée |
| `0011_boucle_relance.sql` | Boucle de relance : délais de relance par température dans `reglages` ; colonnes `prochaine_action_le` (tenue par la base d'après les tâches à faire) et `sans_prochaine_action_le` (absence confirmée) sur `contacts` ; fonction `boucler_tache` (tâche faite, activité consignée, prochaine action créée ou refus confirmé, en une seule opération) |
| `0012_projets_vendeurs.sql` | Table `projets_vendeurs` (vendeur, bien, étape et date d'entrée tenue par la base, découverte, estimation, concurrence, mandat signé, état et sorties) avec ses critères de sortie en contraintes ; colonne `projet_vendeur_id` sur `taches` et `activites` ; fonction `sortir_projet_vendeur` (à recontacter ou perdu, avec la relance) ; `cloturer_tache`, `boucler_tache` et `fusionner_contacts` complétées |
| `0013_projets_acquereurs.sql` | Table `projets_acquereurs` (acquéreur, co-acquéreur, étape et date d'entrée tenue par la base, origine de la demande, recherche, financement, état et sorties, offre acceptée) avec ses critères de sortie en contraintes et en déclencheur ; table `biens_proposes` (sélection et réaction de l'acquéreur) ; colonne `projet_acquereur_id` sur `taches` et `activites`, compte rendu structuré des visites sur `activites` ; fonctions `planifier_visite` et `sortir_projet_acquereur` ; `cloturer_tache`, `boucler_tache` (recréée avec le compte rendu de visite) et `fusionner_contacts` complétées |
| `0014_types_biens.sql` | Types de bien sur deux niveaux : `biens.type` devient le type principal (appartement, maison, terrain, commerce) et la nouvelle colonne `biens.categorie` le type secondaire (ancien, neuf, viager ; vide pour un terrain), biens existants reclassés ; `projets_acquereurs.types_biens` prend les types principaux, nouvelle colonne `categories_biens` |
| `0015_visite_reaction_bien.sql` | `boucler_tache` recréée avec deux paramètres de plus : après une visite d'un projet d'achat, la réaction au bien visité (et la raison d'un refus) est enregistrée dans la sélection, dans la même opération |
| `0016_ecran_aujourdhui.sql` | Écran « Aujourd'hui » : table `priorites_du_jour` (les trois actions qui comptent, une ligne par jour) ; fonctions `dernieres_activites` (dernière activité de chaque contact d'une liste) et `projets_sans_activite` (projets en cours sans activité depuis 15 jours, les plus anciens d'abord, avec leur nombre) |
